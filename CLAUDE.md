# CLAUDE.md

Guidance for AI assistants (and humans) working in this repository.

## What this project is

**Archive Portal** is a Plesk → S3 email archiving system with a browsing UI. Its
purpose is to reclaim disk space on a Plesk mail server by moving old mail off the
live mail store into compressed archives in S3 — while keeping that mail verifiable,
restorable, and browsable.

Despite the README calling it a "v1 scaffold (read-only)", the system is deployed and
in active use, and includes archiving, verified deletion, S3 discovery, orphan
pruning, bulk operations, and an ingest/browse path. Treat the README as outdated; this
file and `SERVER_ACCESS_AND_DEPLOY_RUNBOOK.md` are the current source of truth.

Live deployment: `archive.smallgod.net`. Mail/archive S3 bucket: `s3://smallgod-mail-archive`.

## Architecture

- **API:** Node.js / Express (`src/`). Runs under Plesk's bundled **Node 12** via PM2.
- **Database:** MySQL / MariaDB, schema name `mail_archive`. Accessed via `mysql2` pool
  (`src/db.js`). Some operations shell out to `sudo plesk db` to reach the `psa` (Plesk)
  database for mailbox sync.
- **Auth:** JWT bearer tokens (`src/middleware/auth.js`), bcrypt password hashes. Roles:
  `admin`, `domain_admin`, plus per-domain membership in `domain_members`.
- **Frontend:** static vanilla-JS SPA in `public/` (`app.js`, `index.html`, `styles.css`),
  served by Express. No build step.
- **Heavy lifting scripts** (`scripts/`):
  - `archive_account_maintenance.sh` — the core archive/delete engine (see contract below).
  - `ingest_worker.py` — pulls a tarball from S3 and parses messages into the DB for browsing.
  - `sync_primary_emails.py` — maps portal logins to owner emails via Plesk/WHMCS.

### Request → API → script flow

The Express routes (`src/routes/domains.js`) spawn the shell/Python scripts as child
processes and interpret their stdout. The scripts run on the Plesk server with `sudo`
access to maildirs and the `aws` CLI. Routes never touch the maildir directly.

## The archive lifecycle (important)

1. **Archive** (`POST /domains/:d/accounts/:a/archive/create`, or bulk `POST /domains/archive-all`):
   runs `archive_account_maintenance.sh archive` → `find`s maildir files in a date range,
   `tar.gz`s them, uploads tarball + `.sha256` + manifest to S3.
2. **Verify**: the API checks the S3 object exists (`aws s3 ls`). `deletion_status` stays
   `blocked` until verification passes — deletion is gated on a confirmed S3 object.
3. **Delete** (`POST .../archive/delete-messages`): only allowed once `verified` is true.
   Runs `archive_account_maintenance.sh delete` to remove matching maildir files, freeing space.
4. **Ingest** (`GET|POST .../ingest`): `ingest_worker.py` downloads the tarball and parses
   messages into `mail_archive` so they remain browsable/searchable in the portal.
5. **Discover** (`POST .../archive/discover`, `/domains/discover-all`): scans S3 and registers
   archives that exist in S3 but not yet in the DB.

State for each account lives in the `mail_account_archives` table (status, verification,
deletion status, S3 URI, byte/file counts, date range).

## S3 layout

```
s3://smallgod-mail-archive/archive/<YYYYMMDD_HHMMSS>/<domain>/<localuser>/
    <domain>_<user>_<rangetag>_<stamp>.tar.gz
    <domain>_<user>_<rangetag>_<stamp>.sha256
    <domain>_<user>_<rangetag>_<stamp>.manifest.txt
```

`<rangetag>` is `before_<date>` or `range_<from>_to_<to>`. The `<stamp>` is a per-run
timestamp; a single archiving run shares one `<stamp>` across all accounts.

## archive_account_maintenance.sh contract

```
archive_account_maintenance.sh <archive|delete> <domain> <user> <from_date> <to_date> [mode]
```

- Validates domain/user (alnum + `._-`) and dates (`YYYY-MM-DD`) before doing anything.
- Selects files via `find <maildir> -type f ! -path '*/tmp/*' -newermt <from> ! -newermt <next_day>`
  (selection is by file **mtime**).
- Emits a **`KEY=VALUE` stdout contract** the API parses, e.g.:
  - archive: `STATUS=ok|no_files`, `FILE_COUNT`, `SOURCE_BYTES`, `ARCHIVE_BYTES`, `ARCHIVE_S3_URI`
  - delete: `STATUS=ok`, `DELETED_COUNT`
  - errors: `ERROR=<message>` with a non-zero exit code
- When adding/changing script output, update the parser in `src/routes/domains.js`
  (`parseKeyValueStdout` and the callers) in the same change.

## Database tables (mail_archive)

`users`, `domains`, `domain_members`, `mail_accounts`, `folders`, `messages`,
`mail_account_archives`. IDs are UUID strings generated by the app/scripts (`UUID()` or
`uuid.uuid4()`), not auto-increment.

## Environment

Copy `.env.example` → `.env`. Required: `JWT_SECRET`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`.
Optional: `PORT` (default 8080), `DB_HOST`/`DB_PORT`, `JWT_EXPIRES_IN`.

AWS credentials at runtime live under the `centos` home: `/home/centos/.aws/`. The API
explicitly sets `HOME`/`AWS_CONFIG_FILE`/`AWS_SHARED_CREDENTIALS_FILE` when spawning
scripts (see `awsEnv` in `src/routes/domains.js`); preserve this when adding new spawns.

## Running locally

```bash
npm install
npm run dev      # NODE_ENV=development node src/server.js
npm start        # production
```

Note: the archiving/deletion/ingest paths only work **on the Plesk server** (they need
maildir access, `sudo`, the `aws` CLI, and `plesk db`). Locally you can run the API and
exercise auth/DB/browse routes, but not the maildir-touching operations.

Create the first admin user:

```bash
node -e "console.log(require('bcryptjs').hashSync('change-me', 12))"
# then INSERT into users (id, email, password_hash, role) with role='admin'
```

## Deployment

Git push to `main` triggers a Plesk Git auto-deploy; a post-deploy action restarts PM2.
PM2 **must** be invoked with the Plesk Node 12 binary and `--jitless`. Full commands,
SSH access, verification checklist, and restart procedures are in
`SERVER_ACCESS_AND_DEPLOY_RUNBOOK.md` — read it before deploying or debugging the running app.

## Conventions & gotchas

- **Restart required:** code on disk changing does not change behavior until PM2 restarts.
- **Stale frontend:** hard-refresh (Cmd+Shift+R) when testing `public/app.js` changes.
- **Node 12:** the runtime is old and EOL; avoid syntax/deps requiring newer Node.
- **Platform:** the server is Linux (CentOS). Shell scripts must use GNU coreutils syntax
  (`date -d`, `stat -c '%s'`, `sha256sum`), not BSD/macOS variants.
- **Job guarding:** async archive jobs check `job_id` before writing state so a stale job
  cannot overwrite a newer one — keep this guard when editing the job handlers.
- **Deletion safety:** deletion is intentionally gated on S3 verification. Do not loosen
  this without a strong reason.
- **SQL from scripts:** `ingest_worker.py` builds SQL by string interpolation with hand-rolled
  escaping piped to `plesk db`. Prefer parameterized queries (`mysql2` `?`) in API code.
