# Archive Portal API

Backend API and web UI for **archiving email off a Plesk mail server into S3** to
reclaim disk space — while keeping that mail verifiable, restorable, and browsable.

The system runs on the Plesk server, finds old mail in user maildirs, compresses and
uploads it to S3, verifies the upload, and only then removes it from the live mail store.
Archived mail can be ingested back into a database so it stays searchable in the portal.

> For architecture details, the archive lifecycle, the script contract, and gotchas, see
> [`CLAUDE.md`](./CLAUDE.md). For server access, deployment, PM2 restart, and resume
> workflow, see [`SERVER_ACCESS_AND_DEPLOY_RUNBOOK.md`](./SERVER_ACCESS_AND_DEPLOY_RUNBOOK.md).

## Features

- **Archive** mail by date range (`before <date>` or `from/to`) per account or in bulk
  across all domains, with bounded concurrency.
- **Verify** each archive exists in S3 before allowing any deletion.
- **Delete** verified, archived mail from the live maildir to free space.
- **Ingest** archived tarballs back into the database for browsing/search.
- **Discover** archives already present in S3 and register them in the portal.
- **Prune** orphaned S3 archives not tracked in the database.
- **Browse** archived domains, accounts, folders, and messages through the web UI.
- JWT auth with `admin` / `domain_admin` roles and per-domain membership.

## API surface

- `POST /auth/login`, `GET /auth/me`, `POST /auth/logout`
- `GET /domains`, `GET /domains/:domainId`, `PATCH /domains/:domainId`
- `GET /domains/:domainId/accounts`, `.../folders`
- Archive: `POST /domains/:d/accounts/:a/archive/create`, `.../archive/verify`,
  `.../archive/delete-messages`, `GET .../archive-state`
- Ingest: `GET|POST /domains/:d/accounts/:a/ingest`
- Bulk/discovery: `POST /domains/archive-all`, `GET /domains/archive-all/progress`,
  `POST /domains/:d/archive/discover`, `POST /domains/discover-all`, `POST /domains/prune-orphans`
- Messages: `GET /messages/folders/:folderId/messages`, `GET /messages/:messageId`
- `GET /health`

## Setup

1. Copy `.env.example` to `.env` and set DB credentials and `JWT_SECRET`.
2. Install dependencies and start:

   ```bash
   npm install
   npm start        # or: npm run dev
   ```

The API listens on `PORT` (default `8080`).

## Important notes

- The **archiving, deletion, and ingest** operations only work when running **on the Plesk
  server** — they require maildir access, `sudo`, the `aws` CLI, and `plesk db`. Running the
  API elsewhere supports auth, DB, and browse routes but not the maildir-touching operations.
- Deletion is **gated on S3 verification**: mail is never removed from the live store until
  its archive is confirmed present in S3.
- New records use UUID strings in `id` columns, generated by the app/scripts.
